PROJECT ROADMAP — FREE REAL-TIME MARKET ANALYSIS TOOL
====================================================

PROJECT GOAL
Build a free-first crypto market-analysis platform that gives traders useful market context through live charts, order flow, liquidity, statistics and customizable alerts. This is an analysis tool only; do not implement trade execution in the initial scope.

GUIDELINES FOR THE AI CODING MODEL
- Follow this roadmap in order. Work on ONE module at a time.
- Before coding a module, inspect the existing project and summarize the implementation plan.
- Prefer proven, free/open-source libraries and existing GitHub projects over building every feature from scratch. Before adopting code, verify recent activity, license, dependencies, tests/CI, security issues, and fit with this architecture.
- Do not clone or copy a whole project blindly. Reuse focused libraries/components where practical; preserve required copyright/license notices and record what was adopted.
- If a candidate repository looks abandoned, has very little history, or lacks a clear license, use it as a reference only—not as a production dependency.
- Do not rewrite working modules without a clear reason. Keep changes small and modular.
- Use free/open-source tools and public exchange market-data APIs wherever possible. Never assume an API, hosting tier or dataset is unlimited or free; verify current terms and limits.
- Use TypeScript end-to-end where practical. Keep code strongly typed, documented and testable.
- After each module: run lint/type checks/tests, fix errors, update this file's checklist, and report changed files plus any manual setup steps.
- Do not add paid services, API keys for market data, or trading/execution endpoints unless explicitly approved.
- Never describe visible orders as confirmed institutional trades. Distinguish observed data from estimates.

INITIAL TECH STACK
- Frontend/toolchain: React + TypeScript managed with Vite+ (`vp` CLI), NOT a plain Vite-only setup. Vite+ is the unified toolchain that includes Vite and related build/test/lint/format tools.
- Vite+ official guide: https://viteplus.dev/guide
- Charts: TradingView Lightweight Charts (follow its attribution/license requirements)
- Backend: Node.js + TypeScript; run backend tasks through the workspace/task scripts where appropriate
- Live data: exchange-native public WebSocket APIs; REST for snapshots/history where permitted
- Initial persistence: SQLite for local development; keep storage behind an interface
- Alerts: Telegram Bot API (user supplies their bot token and chat configuration)
- Testing/checks/builds: use Vite+ commands (`vp test`, `vp check`, `vp build`) where supported by the chosen template; use `vp run <task>` for project-specific tasks
- Version control/project tracking: Git + GitHub Issues/Projects

HIGH-LEVEL ARCHITECTURE
Exchange adapters -> normalized market-data events -> market-data service/cache -> analytics and alert engine -> API/WebSocket -> React dashboard
                                                      |-> SQLite history
                                                      |-> Telegram notification worker

SCOPE GUARDRAILS
- Start with one exchange, a small symbol list and a few timeframes.
- Reuse proven open-source components when they fit; do not rebuild charting, indicators or rendering primitives without first evaluating available projects.
- Before adding any dependency or copying code, verify current license compatibility, maintenance activity and security posture; document the choice in OPEN_SOURCE_REUSE.md.
- Do not begin with machine-learning predictions, auto-trading, paid feeds, or a complex multi-user cloud system.
- Do not claim the tool predicts price or guarantees an edge. Present measurements, conditions and uncertainty.
- Respect exchange terms, rate limits, attribution and redistribution restrictions.
- Keep secrets on the backend and out of source control.
